## 表单

空白 issue 关掉了，开 issue 只能从三张表单里选（`.github/ISSUE_TEMPLATE/`），入口下方另有常见问题、文档和「点个 Star」三个链接。

| 表单 | 自动带的标签 | 必填 |
|---|---|---|
| 问题反馈 | `bug` | 版本号、部署方式、涉及的账号类型、问题描述、报错原文和运行日志 |
| 功能建议 | `enhancement` | 想解决什么问题、希望怎么做 |
| 使用求助 | `question` | 版本号、部署方式、想做什么卡在哪 |

GitHub 只拦空着的必填项，填了 `latest`、`无` 这类等于没填的内容拦不住，由下面的信息检查补上。

## 标签

只留这 5 个，没有别的标签：

| 标签 | 怎么打上的 | 作用 |
|---|---|---|
| `bug` | 问题反馈表单自动带 | 信息检查只查带 `bug` 的 issue |
| `enhancement` | 功能建议表单自动带 | 分类 |
| `question` | 使用求助表单自动带 | 分类 |
| 待补充 | 信息检查发现缺项时自动打；维护者也可以手动打 | 打上就开始 14 天倒计时；作者回复后自动摘掉 |
| 即将关闭 | 待补充 11 天没动静时自动打 | 提醒还有 3 天关闭，不用手动打 |

`bug`、`enhancement`、`question` 三个名字不能改：表单按名字打标签，信息检查按 `bug` 认问题反馈。GitHub 默认的 `duplicate`、`wontfix`、`invalid` 等已经删掉，用[关闭理由](#关闭时选理由)代替。

## 自动处理

**信息检查**（`.github/workflows/issue-check.yml`，规则在 `.github/scripts/issue-check.js`）：

- 带 `bug` 的 issue 新开或改了正文时，查版本号（要有 x.y.z，`latest` 不算）、部署方式、账号类型、报错原文和运行日志（只写「无」「没有」不算）。缺了就留一条机器人评论点名要补什么，打上「待补充」；之后再查只更新这一条评论，不重复留言。
- 补齐后，那条评论改成「信息齐了」，摘掉「待补充」和「即将关闭」。
- 作者在打着「待补充」的 issue 下回复：直接摘掉这两个标签，停止计时；issue 已经因为超期被关掉的，自动重新打开。
- 维护者（仓库所有者、成员、协作者）自己开的 issue 不查，但手动打的「待补充」照样计时。

**超期关闭**（`.github/workflows/issue-stale.yml`，每天 UTC 02:17 跑一次，也可以在 Actions 页手动触发）：

- 只管打着「待补充」的 issue。从最后一次有人回复或改动算起，11 天没动静打「即将关闭」并留言提醒，再过 3 天没动静就以「不计划」关闭，留言告诉对方补上信息回复一下会自动重新打开。
- 期间任何人回复或改动都重新计时，下一次运行时摘掉「即将关闭」。

## 维护者平时怎么用

原则：**「待补充」只在等提问的人时打。** 等自己查、自己修、等发版时不要打，已经打了就摘掉，不然到期会被自动关闭。

| 情况 | 怎么做 |
|---|---|
| 新 issue 进来 | 表单开的已经带好分类标签；问题反馈缺信息的，机器人会留言并打「待补充」，不用管 |
| 选错了表单（比如用问题反馈提建议） | issue 页右侧栏点「Labels」，取消 `bug`、勾上 `enhancement`；机器人打了「待补充」的一起取消 |
| 要对方补机器人查不出来的东西（某段日志、复现步骤、配置） | 先回帖说清楚要什么，再在「Labels」里勾上「待补充」 |
| 对方回复了 | 「待补充」自动摘掉；回复了但还不够，就再回帖追问、重新勾上「待补充」 |
| 看到「即将关闭」 | 还剩 3 天。想再等等就随便回一句，重新计 11 天；不想让它关就取消「待补充」 |
| 被自动关闭了 | 不用管：对方回复会自动重开 |
| 修好了，但对方一直没回 | 发版后自己回一句哪一版修了，按「已完成」关闭，别等它以「不计划」自动关 |

## 关闭时选理由

点 issue 底部「Close issue」按钮右边的小箭头选：

| 理由 | 用在 |
|---|---|
| 已完成（completed） | 修好了、做完了、问题回答完了 |
| 不计划（not planned） | 不打算做、不是本项目的问题、内容无效；超期自动关闭也用这个 |
| 重复（duplicate） | 和已有的 issue 重复，选它后填原 issue 的编号 |

## 改规则要动哪些地方

- **问题反馈的必填项**：`.github/ISSUE_TEMPLATE/1-bug.yml` 和 `.github/scripts/issue-check.js` 的 `CHECKS` 一起改，检查按表单里的标题文字找对应的项，两边的标题要一字不差；再改 `issue-check.test.js` 和 README 的[反馈问题](../README.md#反馈问题)。测试命令：`node --test '.github/scripts/*.test.js'`（CI 的前端任务也会跑）。
- **天数**：`issue-stale.yml` 的 `days-before-issue-stale`（打「即将关闭」）与 `days-before-issue-close`（再过几天关），两者相加是总天数；同步改两条留言、机器人评论里的「14 天」、两个标签的说明、README 和本文。
- **标签名**：「待补充」「即将关闭」写在 `issue-check.js` 开头和 `issue-stale.yml` 里，改名要连仓库里的标签一起改。
