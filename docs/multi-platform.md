# 多平台上游接入（实验）

首期在 WorkBuddy 之外增加 TraeWork 国内、Trae Code 国内和 Qoder 国内／国际。TraeWork 国内与 Qoder 国内曾完成指定模型的真实三协议文本／SSE、权限隔离、设备令牌刷新与重启恢复验收；Qoder 国内另通过 Claude Code／Codex 工具闭环，两平台均观察到官方 credits 扣减。最新回归中 Trae Code 国内指定模型的流式正文与结束通过，Qoder 国内因资源排队未恢复生成，国际版在网关和官方客户端中均无可用模型。完整验收、其他目录模型与逐请求费用仍待确认，面板保持实验接入和 `validated:false`。当前待办见[真实账号验收待办](#真实账号验收待办)，协议依据见[官方客户端对照](official-client.md#新增平台的协议依据与验收边界)。

## 产品、地区和模型名

| 上游标识 | 模型写法 | 当前入口能力 |
|---|---|---|
| `workbuddy:cn` | `cn:模型名`（旧写法保留） | 原有全部能力 |
| `workbuddy:global` | `global:模型名`（旧写法保留） | 原有全部能力 |
| `traework:cn` | `traework:cn:模型名` | 文本对话，三协议入口，SSE；不接受客户端工具调用 |
| `traecode:cn` | `traecode:cn:模型名` | 文本、客户端工具调用和结果回传、多轮、三协议入口、SSE |
| `qoder:cn` | `qoder:cn:模型名` | 同上，使用国内 Qoder 线路 |
| `qoder:global` | `qoder:global:模型名` | 同上，使用国际 Qoder 线路 |

模型名从账号目录实时读取并缓存 30 分钟；面板「刷新模型」强制更新。没有静态模型列表兜底。目录中的模型能否实际调用、其工具能力及消耗哪类额度，仍需真实账号验收；协议测试通过不代表每个模型均已验收。

TraeWork 走 `solo_work_remote` Work 会话接口，Trae Code 走 `chat_v3` 对话接口。即使两通道共用同一份账号凭证，错误、限额或工具需求也不会使请求自动换到另一个产品。Qoder 国内和国际也不互相回落。首期不支持图片、平台远程工具的对外暴露、签到或成长任务；不把图片内容静默删掉后发送。

文本内容可以使用字符串或纯文本段数组。Qoder 会按顺序合并文本段，保持原有空白，并将同一文本填入消息历史、系统提示词和当前问题上下文；客户端工具结果同样保留。Messages 工具结果中的图片、文档等非文本段会在入口翻译前直接返回 400，避免翻译时丢失后仅发送剩余文字。

## 添加账号

所有平台统一在「账号池」管理。仅使用 WorkBuddy 时，首屏显示原有状态与积分，搜索、地区和分组筛选放在账号列表内。接入 Trae、Qoder 或仍有其历史用量时，顶部显示产品统计和跨平台筛选，可组合产品、地区、名称／备注／账号 ID 与分组；同一 Trae 账号即使同时开通 Work、Code 通道，也只计一个账号。原「平台账号」导航已合并，旧 `#/providers` 链接会转到账号池。

点击面板右上角「添加账号」，先选「产品与地区」，再按该平台的方式添加。WorkBuddy 国内／国际使用原有浏览器登录或 JSON 文件导入。Trae、Qoder 在「浏览器登录」或「导入凭证」标签内选择出站代理并完成添加。

- **网页授权**：Trae 使用 PKCE；官方授权页要求回调地址使用 `http://127.0.0.1:1024/authorize`，不接受 `localhost`。网关接收回调中的 `authCodeInfo.AuthCode`，向 `api.trae.com.cn` 兑换令牌。直接在本机运行时可自动接收回调；容器或远程部署时，若回调页面无法打开，复制地址栏中的完整回调地址粘贴回面板。回调尚未到达时，点击检查会提示等待；成功保存后释放本地回调端口。Qoder 使用设备授权，完成官方网页授权后点「检查并保存授权」；轮询返回 404 表示仍在等待，不作为授权失败。国内版直接保存设备令牌，不兑换 job token；国际版继续使用 job token。授权会话保留 15 分钟，服务器不返回 PKCE verifier、设备私钥或 token。兑换成功但保存失败时，可在会话过期前重试保存，不重复兑换 Trae 授权码。Qoder 在获取设备令牌、国际版兑换 job token、查询用户信息及保存账号之间发生错误时，保留已完成阶段的结果，再点「检查并保存授权」即可继续；用户信息未返回稳定账号身份时拒绝保存，不能用轮询结果中的身份跳过核验。
- **Trae 凭证导入**：填写本仓库的完整凭证 JSON，字段为 `access_token`、`refresh_token`、`expires_at`（Unix 秒）、`uid`、`machine_id`、`device_id`、`client_id`、`device_key`。设备绑定凭证须保留原设备 ID 和 PKCS8 P-256 PEM 私钥。网页登录会生成并保存设备密钥；不把已有账号的设备私钥替换成新私钥。
- **Qoder PAT 导入**：直接粘贴 PAT；也可填写含 `pat` 的凭证 JSON。服务端兑换短期令牌并从账号状态获取签名用的 `userType`，不猜测订阅档位。完整 Qoder 凭证可含 `access_token`、`refresh_token`、`token_kind`、`expires_at`、`uid`、`user_type`、`machine_id`、`machine_token`、`machine_code`、`machine_type`、`machine_os`、`machine_hostname`；迁移字段应来自原官方客户端，hostname 使用其已规范化值；从未使用官方客户端的账号由服务端实际运行环境首次初始化，不替换已有 MachineID／DeviceID。上述设备字段刷新、重启和导出后保留，不出现在普通账号列表。网页登录产生的 `token_kind` 国内为 `device`、国际为 `job`。设备令牌的 `expires_in` 按秒读取，job token 按毫秒读取；设备刷新使用原有机器身份，并读取 `device_token` 及新的刷新令牌。

稳定账号 ID 由平台族、地区和上游 UID 派生。相同 UID 在 Qoder 国内与国际是两个账号；Trae 国内的 Work／Code 是同一账号下的两个明确通道，需要分别添加。重新导入会更新凭证并加入选中的通道，保留已有分组、优先级和人工停用设置。不要只靠显示名称判断账号身份。

首次使用 Qoder、从未运行过官方客户端时，不存在需要迁移的「原设备 UMID」。网关在首次授权保存、导入或账号请求时，按官方 1.1.89 流程取得并校验外部 helper，在实际服务环境初始化设备身份并持久化；之后按需约一小时刷新，失败保留旧快照。已导入的身份继续透传，不被本机生成值覆盖。自动初始化限 Linux，绑定／默认代理时阻止 helper 绕过代理直连；其他平台、代理边界及完整备份路径见[Qoder 设备身份](qoder-device-identity.md)。

账号导入一次处理一个请求。重新导入已有账号时，先检查在途请求并占用刷新锁，再进行认证；账号正在对话或刷新时直接拒绝，不先消费刷新令牌。凭证缺少 UID 但与已保存的 token、刷新令牌或 PAT 相同时，也按已有账号处理。导入期间不允许移除账号或另起目录刷新。

可以在账号「设置」里改名称、分组、优先级、代理和停用状态；优先级越小越先用。相同优先级按最近使用时间轮换。每个账号最多一个在途对话。等待本地账号空位共用 `pool.in_flight_wait`，默认 30 秒，设为 `0` 立即返回 `503 account_queue_timeout`。累计等位超时返回同一错误。所有新平台合计最多 512 个等待请求，每个调用密钥最多 64 个，队满返回 `429 account_queue_full`。排队取消会释放等待名额。可重试的账号故障冷却 30 秒。目录缺少请求模型只跳过该账号，保留其他模型的可用性。移除正在刷新或执行请求的账号会被拒绝。

Qoder 上游返回 `10605` 时，未输出业务帧的请求会在原账号、原会话和请求集内查询队列，按上游重试时间等待；就绪后更新请求 ID 重发。累计排队最多一小时、最多恢复十次，API 既有的十分钟总期限和单号测活的 90 秒期限优先。客户端断开或请求期限到达会提前退出，并发送最长 3 秒的队列释放请求。已确认进入队列且在输出前中断的请求，其错误详情保留 `10605` 及原中断原因。已输出后不重放，等待期间继续占用该账号在途槽位；排队流程不保证一定获得模型资源。

## 密钥授权与选路

在「密钥」中明确勾选允许的上游，并选择裸模型名的默认上游。

- 旧密钥没有这两个字段时，仅允许原有 WorkBuddy 国内／国际，裸模型名沿用原来的跨域规则。增加新平台账号不会扩大旧密钥的权限。
- 指定 `qoder:global:模型名` 等完整名称时，固定产品和地区；裸模型名按密钥的默认上游解释。默认上游必须属于允许的上游。
- 未设默认上游时，裸模型沿用 WorkBuddy 逻辑；如果密钥仅允许一个 WorkBuddy 地区，裸名固定到该地区。只允许新平台的密钥应填写默认上游或始终使用完整模型名。
- 管理员密钥不受客户端密钥的上游、分组或用量约束；管理员调用新平台请使用完整模型名。
- 分组、停用、到期、上游范围和模型白名单会在选号及发出请求前重新检查。WorkBuddy 刷新凭证后及 WorkBuddy／Qoder 排队重送前再次核验；已收回权限时释放队列并返回 403。某组没有可用账号时回 503，不借组外账号。
- 平台前缀后须包含原生模型 ID。空模型名返回 `400 invalid_model`，不会占用账号或写入尝试账本。
- 先在权限范围内筛选账号，目录缺失或过期时先刷新。目录不匹配不占轮换次数，也不记一次尝试用量。所有可选目录都不匹配时返回 `404 model_not_available_for_account`。
- Qoder 返回空模型列表或全部停用时，普通目录查询复用已确认的结果 30 分钟，手动刷新可提前更新。对话遇到该结果时，网关在尝试上限内继续选择同产品、同地区且已授权的其他账号。目录不可用的尝试计为失败，积分保持未知，账号不进入推理冷却。指定账号的测活仍只尝试该账号。
- 同一账号和上游的普通目录查询共享一次在途刷新，等待者取消会释放自己的等待。面板强制刷新独立发起。并发刷新目录时，较晚发起且已确认的结果优先，包括空列表及全部停用。迟到的旧响应沿用此结果，临时查询失败仍保留最后一次有效目录。
- WorkBuddy 白名单沿用裸模型名，例如 `glm-*`。新平台白名单使用完整名称，例如 `qoder:global:claude-*`；旧裸通配 `*` 不会匹配新平台模型。白名单为空表示允许授权上游中的全部模型。
- `/v1/models` 只列本密钥可访问的模型和新平台账号目录；`models.hidden` 支持完整新平台名称，并同时阻止列出和调用。裸隐藏项仍只作用于 WorkBuddy 两地区。
- 开启 WorkBuddy 跨域时，客户端密钥仍能看到可用的裸模型名；其 `realms` 和模型属性只来自该密钥可选的地区。默认上游固定为某个 WorkBuddy 地区时，裸名只来自该地区；默认上游为新平台时，WorkBuddy 仅列带地区前缀的名称，避免裸名选到另一产品。目录查询等待上游期间修改平台、分组、模型白名单或隐藏项，返回前按新权限和配置过滤；期间删除、停用或到期的密钥返回 401。
- 网关内置联网搜索使用 WorkBuddy。新平台模型的搜索请求会明确拒绝；可使用客户端实现的搜索工具，不会为了搜索静默消耗 WorkBuddy 账号。

显式的产品／地区前缀不应用模型别名规则。新平台设为默认上游时，裸名直接解释为该平台模型；需要把 Claude Code 的默认官方名称映射到其他模型时，请配置客户端模型变量为目录中的完整名称。

## Claude Code 和 Codex

三种入口共用同一执行链，原有端点不变：`/v1/chat/completions`、`/v1/messages`、`/v1/responses`。例如，已给密钥允许 `qoder:global` 且默认设为它：

```bash
# Claude Code，Base URL 不带 /v1
export ANTHROPIC_BASE_URL="http://localhost:8080"
export ANTHROPIC_API_KEY="sk-client-example"
export ANTHROPIC_MODEL="qoder:global:替换为目录中的模型名"
```

Codex 的 provider 配置沿用[API 参考](api.md#codexresponses-api)，把 `model` 改成 `traecode:cn:目录模型名` 或 `qoder:global:目录模型名`。当默认上游已配置时，也可使用裸模型名。

工具调用在客户端执行；网关传递工具定义、调用 ID、参数片段和工具结果。假上游测试覆盖流式／非流式的并行调用和工具结果回传。已输出任何上游帧后发生错误，不换账号重新生成；流中返回错误并结束，不伪造成功完成事件。正常结束信息等上游完成标记、有效结束原因与会话／用量保存均成功后才发送；先收到 token 用量也不会提前结束 Anthropic 消息。Qoder 的显式 `event: error` 同样按失败处理，即使事件正文没有 `error` 字段、后面仍有完成标记，也不会改判成功。非流式请求完整收齐再聚合返回。

Qoder 支持外层 `data: [DONE]` 和包络 `body: "[DONE]"` 两种完成标记；后者在读取后直接结束，不等待连接关闭，不把控制标记送去解析 JSON。包络 `code`、`statusCodeValue` 或错误字段／事件表示失败时仍报错，缺少有效结束原因也不会正常收尾。此修正避免正常回复和用量已返回后，测活仍因解析完成标记而误报失败；修正前保存的测活结果与历史统计不会被重写，需重新测活生成新结果。

TraeWork 会话请求按官方网页构造：文本和历史顺序合并后编码为 `query` 文本块 JSON，模型目录转换为明确的请求模型描述，Work 能力标记放在请求顶层；目录缺少 `config_source` 时在创建会话前报错，需重新获取目录。创建会话与订阅事件的错误会注明失败阶段，并保留上游状态和业务码；HTTP 500／`995000` 本身不足以判断是模型不可用或账号异常，也不触发跨产品回落。

## 单号测活

Trae、Qoder 账号卡片提供与原账号池一致的「测活」入口：打开弹窗，选择已开通的产品与地区、从该账号实时目录选择模型，点击「开始测活」。目录中的重复模型会在选择器中去重；没有价格依据，不提供「自动最便宜」。测试给指定账号发送一条「hi」，请求短回复，展示成功／失败、状态码、首字与总耗时、上游回复及已知 token。上游是否严格遵守短回复限制未确认，可能消耗平台额度；没有返回的 token 仍显示未知。

测试固定该账号及产品，只尝试一次，不轮换其他账号，不读取或改写粘性会话。人工停止派发的账号可手动测试，测通后仍保持停用；临时冷却可在测通后解除。账号有在途请求时不排队；凭证刷新保护、代理限制和隐藏模型规则照常生效。关闭弹窗后测试继续，最长 90 秒。上次测活结果保存在 `providers.json`，重启仍可在卡片查看，回复正文不落盘。

测活走真实对话执行链，记入请求记录（路径 `/panel/liveness`、密钥名「测活」）和该平台账号的用量（密钥维度 `liveness`），不消耗客户端密钥的限额。WorkBuddy 原有单号、批量与定时测活继续使用原流程。新平台支持手动单号测活，以及选中账号后的批量测活；批量测活必须先在每个账号设置中保存完整模型名，没有配置的账号逐项报错，不猜价格、不自动跨产品。全局定时测活开关和间隔也覆盖新平台，但只探测已配置模型、存在临时冷却记录且未人工停用、未暂停、未处于刷新保护、没有在途请求的号；成功后解除冷却，结果标记为定时测活。冷却到期后的普通对话成功也会清除冷却记录，避免额外发起定时测活。没有保存测活模型的已有账号不会因升级而自动发起推理。

管理员接口：`POST /panel/api/providers/accounts/{id}/liveness`，请求 `{"model":"qoder:cn:目录模型名"}`，返回 `{"result":{…},"reply":"…"}`。必须给完整产品／地区模型名；账号不存在回 404，缺模型或请求格式错误回 400，测活未接入回 501，参数不属于该账号或结果保存失败回 422。已执行的上游失败写在 `result.ok=false` 与错误详情中。

## 代理和用量

新平台可以显式选择代理页里已有的代理，授权、导入、刷新、目录与推理共用该线路；默认线路复用原有出站传输层及环境代理。打开「只许走号的代理」后，未选代理的新平台账号也不能出站；代理删除、到期或不可用时不回退直连。平台 HTTP 请求遇到重定向时在原端点终止并报错。新平台继续显式绑定，不参与 WorkBuddy 默认代理池自动分配、代理容量计数或自动改绑；修改代理后原有设备身份保持不变。账号池支持逐号或批量选择已有代理，代理页另列平台显式绑定的账号名和数量，避免与 WorkBuddy 的池容量混淆。代理删除提示明确列出受影响的平台账号；删除后它们停止出站，需重新绑定，不回退直连。

普通对话在发送上游生成前遇到绑定代理故障，会在同一产品和地区按权限、模型与重试预算继续选号。连接失败会将代理标为不可用，账号无需等待冷却。上游已创建 TraeWork 会话、已接受 Qoder 请求排队、客户端已收到响应或已取消时，停止换号。没有可用线路时返回 HTTP 503，客户端错误不包含代理名称和地址。刷新请求确认未发出时，原刷新令牌仍可使用；兑换结果不确定时，账号继续受刷新保护。

Qoder 国际版读取模型目录时，连接失败或 HTTP 502／503／504 会在本账号、原线路的官方发现候选中切换，上游目录发现与读取共用十秒预算，最多尝试三个不同节点。失败节点从本次缓存移除，后续查询沿用剩余节点。401／403、限流、上游业务错误和全部停用结果会直接返回。已经开始的生成、排队轮询和队列释放继续使用原节点。

账号池单独显示按上游、账号、模型和客户端密钥汇总的 Trae／Qoder 请求与 token 用量，并按当前账号、产品与地区筛选。请求数包含上游尝试，失败单列；`tokens_known` 是提供完整输入／输出 token 的尝试数，缺失记未知。Qoder 按官方响应接入单次 credits，Trae Work 按用户消息 ID 查询费用；Code 当前路径缺少可确认的单次扣费字段，仍记未知，详细口径见下方逐请求费用记录。不将新平台用量折算成 WorkBuddy 积分，不把“尚未查询余额”显示为零余额。Trae 国内和 Qoder 国内／国际的官方额度已接入账号池和积分构成页，保留上游原始数值与单位，不用余额差推算单次费用。新增请求同时进入原有 `usage.json` 时序账本，在「用量」页支持时间范围、上游、客户端密钥以及账号／模型／上游／密钥明细；未返回完整 token 的尝试另记 `unknown_tokens`，合计和图表只汇总已知部分。新平台模型使用完整前缀，避免同名模型混合。旧 `providers.json` 累计记录没有时间，保留为「历史累计」，不补造时间、不重复导入时序账本，且明确不受时间筛选影响。

客户端密钥的请求次数和已知 token 上限跨平台合计。新平台尚未选到账号便取消本地排队时退还次数；已进入账号处理后由客户端取消时仍计一次，流式与非流式口径一致。流式正文或结束事件写入失败时也照计一次。上游失败会退还次数；以上情况中已收到的有效 token 用量均保留计量。客户端取消及流式响应写入失败记录为 `interrupted`，不会伪装成功，也不换账号继续生成。积分上限只约束 WorkBuddy，不能用 WorkBuddy 积分上限限制 Qoder 或 Trae 费用。新平台请求记录带 `target`、派生的 `account_id`、`tokens_known`，模型字段保留产品／地区前缀；WorkBuddy 仍只记录截断的账号标签，不新增完整上游 UID。

## 官方账号额度

账号池卡片显示 Trae／Qoder 的官方余额与总额、请求统计和最近测活。用量来自当前产品与地区筛选下的历史累计；只有部分请求返回 token 时标「已知」。点右上角箭头看额度到期、重置、更新时间和模型目录，双通道账号可分别刷新模型。「积分构成 → Trae / Qoder 账号额度」显示同一份额度数据，并可展开官方额度包。首次查看没有快照的账号时自动查询，之后切页使用缓存；点卡片底部「额度」或详情里的「刷新额度」强制查询。账号列表的定时轮询只读本地缓存，不打额度接口。服务端同一账号的并发查询合并，普通查询缓存一分钟。

- Trae 国内使用账号级汇总，Work／Code 多通道共用一次查询和快照，专用产品额度池归属未确认。credits／USD 按计费标志区分；标志同时为真、同时为假或缺失时，单位显示未确认。包内 `credits_limit`／`credits_amount` 仍使用 credits，不与汇总相加、不倒推包剩余；`-1` 包限额按官方不限量语义显示。空用量显示未知，隐藏包另行标注，包状态枚举尚未确认，不据此推断可用性。
- Qoder 国内／国际保留 `userQuota.total/used/remaining/unit` 原值，不用「总额 - 已用」替换官方 remaining；支持 `displayMode=qoder` 的 `qoderUsage`，其他响应明确报未支持。国际版额度已核对官方 CLI 并从服务容器查询成功，复用账号池与积分构成页的展示、缓存和持久快照。
- 缺失数值显示未知，明确的零显示零。各账号、平台、单位分别展示，不折算 WorkBuddy 积分，不跨单位合计。到期／重置时间只在官方返回时显示。
- 成功快照随账号写入 `providers.json`，重启保留；查询失败显示错误和尝试时间，并保留上次成功数值及其更新时间。查询错误独立于推理错误与冷却，不据此自动停用账号；但若查询所需的令牌刷新失败，仍沿用原有的刷新保护和停止派发规则。
- 查询复用账号代理、最新凭证及刷新锁；在途时禁止换代理、删号、重导入和导出。余额不是实时扣费账本，需手动刷新查看后续变化。

## 文件、升级与恢复

- WorkBuddy 原有 auth、`state.json`、`sessions.json`、`usage.json` 文件继续使用原路径与语义。
- `providers.json` 版本 2 保存新平台凭证和账号设置。同目录的 `providers.json.activity.json` 保存用量汇总与会话快照，`providers.json.attempts.json` 保存快照后的近期尝试。三份文件均为 `0600`。尝试带有网关请求 ID 和尝试序号，每 128 次合并快照。重启按流水号恢复。绑定按密钥和上游隔离，有效期 24 小时。移除账号保留用量，重新导入同一身份也不会复活旧绑定。
- 从版本 1 启动时自动迁移原用量与会话，两份账本安全落盘后才切换账号文件版本。迁移中断可再次启动。备份时停服务并保留整个数据目录，降级应恢复升级前的整套备份。
- 上游已完成但账本未能确认时，请求记录显示「上游已完成，账本待补写」。非流式调用返回 502，流式调用以错误结束。网关按原尝试记录在后续请求前、后台每 30 秒及正常停机时补写。故障持续时暂停新推理并返回 `503 ledger_unavailable`。此时内存含待写记录，如果进程在账本仍不可写时终止，这部分记录可能丢失。请求记录的结果反映当时的交付状态。
- `api_keys.json` 首次从 v1 升级时，先原子发布原文备份 `api_keys.json.v1.bak` 并逐字节核验，另存 SHA-256 校验文件 `api_keys.json.v1.bak.sha256`。升级后旧密钥保留 WorkBuddy 范围。再次升级会核验首次备份；旧版运行期间如已修改密钥或用量，新快照另存为 `api_keys.json.v1.<SHA-256>.bak`。核验或写盘失败会中止迁移，保留当前 v1 文件。
- v2 使用字符串版本标记。早期数字版本 2 在启动时转换。面板会拒绝退回无法读取该格式的自带版本。一键升级跨越该格式边界时，网关先发布独立的新版密钥文件 `api_keys.json.<摘要>.v2`，再把旧路径原子切换为只含一条已停用、已过期占位记录的 v1 文件。发布入口之前启动失败，旧程序仍读取原活跃文件；发布后自动回退，旧程序可启动管理面板，客户端密钥保持关闭。保留该占位记录，再次升级会载入最新的 v2 密钥、权限和计数，并合并回退期间在旧面板新增的密钥。备份数据目录时一并保存入口和关联的 v2 文件。手动降级时先停服务，备份完整数据目录，再把所选 v1 备份复制为 `api_keys.json`，最后启动旧版。请核对所选快照的密钥集合和计数，包括当时仍有效、之后已撤销的密钥。
- 账号刷新按账号加锁，先落盘刷新中标记，再兑换和保存新令牌；只有新令牌安全落盘才继续派发。刷新响应未给出稳定身份时，使用新令牌读取用户信息。仍缺少身份或身份与原账号不一致时，保留原凭证并停止派发。进程中断、刷新返回不确定错误、身份异常或落盘失败时，`.refresh-账号ID` 标记使重启后的账号继续停止派发，避免重放可能已消费的旧刷新令牌。使用完整的新凭证重新导入恢复，不要只删标记继续用旧令牌。
- 请求已取消时不再选号；取得刷新锁后若发现请求已取消，不写刷新标记、不兑换令牌，避免尚未出站就把账号置为需要重新授权。
- 重新导入能由 UID 或原凭证定位的账号时，认证沿用已有绑定代理。更换代理在账号设置中显式操作。恢复 Trae 双通道备份时，两条记录共享首次安全保存的新令牌。同一身份被移除后重新授权，也在新凭证落盘后清除旧刷新标记；清理失败会报错并继续阻止派发。重新导入已有账号需要刷新令牌时，同样先写刷新中标记。认证失败、刷新后身份变化或新凭证保存失败时，原账号设置与凭证保留，并停止派发；重启后保护仍有效。此时重新授权，或导入无需再次刷新的有效新凭证恢复，不能用过期的旧凭证再次兑换。
- 平台账号或用量文件保存失败会向调用方报错；不会当成空账号库继续启动。备份整个数据目录时一并保留 `providers.json`、两份平台账本、密钥备份和刷新中标记，不在公开 issue 中粘贴这些文件。

## 每次请求的计费积分

请求记录的「积分」列展示该次上游调用已确认的实际扣费，保留小数精度。`credit_known=false` 表示未知，明确免费才显示零；`credit_unit` 保留官方单位。失败或下游取消后已经收到的有效扣费仍记账，重复累计帧只取同一次调用的最新观测，不重复累加。

| 上游 | 单次扣费依据 | 当前边界 |
|---|---|---|
| WorkBuddy | 原有 `usage.credit` | 保留既有口径 |
| Qoder 国内／国际 | 官方 CLI 的 `usage.credits` 与 `usage.billable` | `billable=false` 按零，`true` 且有有限非负 `credits` 才已知；`original_credits` 是原价，不参与扣费。缺字段保持未知；真实生成扣费仍受国内资源排队及国际空模型目录阻挡，目前已核对官方源码并完成离线三协议验证 |
| Trae Work 国内 | 官方 `get_session_usage`，`session_id` 使用创建会话返回的用户 `message_id` | 已从服务容器取得已结算响应，并核对返回的 `session_id` 与本条用户消息一致。正数才确认；零或无结果无法区分免费与未结算，保持未知 |
| Trae Code 国内 | 当前 `llm_utils_chat` 原始流及官方费用接口只读对照 | 流中有 Token 用量；用可复用会话 ID 查到一条零金额会话明细，明细缺少单次请求归属及结算状态，逐请求费用保持未知 |

Trae Work 在流结束或中断后查询本条消息费用，沿用当前账号和代理，保留下游取消前的请求上下文值。初查为空或为零时，在开始查询两秒后补查一次，两次查询合计最多三秒。只有官方费用接口返回的同消息费用才入账。费用查询失败会记录日志，正文结果仍按生成结果返回。到期仍未结算的费用记为未知，不在请求结束后后台回填。

账号「历史累计」同步显示已知费用、单位及已知请求覆盖率。「用量 → 积分扣除历史」按时间、密钥、账号、模型统计，WorkBuddy、Trae Work、Qoder 国内、Qoder 国际分别展示；混合单位时不提供伪造的全平台积分合计。`credit_by_unit` 提供各单位合计；兼容的 `credits`、`credit_samples` 等平铺字段只在有单一已知单位时提供汇总，混合时为零，调用方应读取 `credit_by_unit`。新平台费用不写入客户端密钥的 WorkBuddy 积分限额。

`usage.json` 升为版本 6，增加与非零 Token 配对的扣费累计，用于准确计算费用／1M Token。只有费用、没有 Token 的样本参与费用合计，不能进入费率分子；小时折叠、持久化、按单位隔离均保留该口径。版本 5 及更早的历史保留原有已观测费用与比例，不倒推不存在的逐请求观测。
