## Docker 部署登录后报「写入 auths/… 失败: permission denied」

容器默认以 uid 10001 运行，而宿主机上挂载的 `auths/`、`data/` 属于你自己，容器写不进去。任选一种解法：

```bash
# 方案 1（推荐）：让容器以你自己的身份运行
docker run --user "$(id -u):$(id -g)" ...
# Compose：
PUID=$(id -u) PGID=$(id -g) docker compose up -d --force-recreate

# 方案 2：把目录交给容器默认用户（需要 sudo）
sudo chown -R 10001:10001 ./auths ./data ./config.json

# 方案 3：以 root 运行（NAS 不方便 chown 时用，自担风险）
docker run --user 0:0 ...
```

## 容器一直显示 unhealthy

镜像的健康检查访问 `/healthz`，而没有可用账号时它返回 503。添加账号后会自动变成 healthy。

## 忘了 api_key

打开配置文件看 `api_key` 字段（Docker 快速开始的配置在 `data/config.json`）。首次自动生成时，启动日志里也打印过一次。

## 429 code=6004 是什么

这是**某个模型**的用量超限，不是账号整体被限流。上游的提示通常带「将在 YYYY-MM-DD HH:MM:SS 重置」：

- 网关把该账号的冷却时间设到上游给的重置时刻（封顶 `cooldown.soft_rate_max`，默认 2 小时）；
- 同一个账号**换别的模型**照样可用；
- 面板「账号池 → 模型锁池」能看到哪些模型被限、还剩几个号、多久解锁。

## 429 code=14003「模型繁忙」是什么

上游说这个模型此刻请求量饱和，几秒到几十秒就会过去（官方客户端遇到它会原样重发，最多等 32 秒）。国际版的 deepseek 常见。

- 网关当场换号重试，只把这个号的这个模型冷却约 30 秒，这个号的别的模型照常可用；
- 所有号的这个模型都在冷却时，网关回 429 并带 `Retry-After`（几十秒），客户端稍等重试即可；
- 号少的域（比如只有两三个国际版号）可能一时全在冷却：`pool.cross_realm` 设成合池（`merge`）或国内版优先（`cn_first`）时，不带前缀的请求会回落到另一个域，带 `global:` 前缀的请求会暂时报错（429 或 503），稍等再试。

## 503「all accounts are busy」是什么

能接这个请求的号都健康，只是在途请求都满了（国内版每个号默认 3 个、国际版 2 个，见 `pool.max_in_flight`、`pool.max_in_flight_global`），或者设了每号每分钟请求数上限（`pool.max_rpm`、`pool.max_rpm_global`）并且到了上限。网关先让请求排队，等有号放出名额再转发，最多等 `pool.in_flight_wait`（默认 30 秒）；等满还没有空位才回这个 503。有号是因为每分钟请求数到上限时，错误信息里写的是 `requests-per-minute`，`gateway_hint` 以 `rpm_full` 开头。

- 偶尔出现：并发的高峰，稍等重试即可；
- 经常出现：同时发的请求比号能接的多，加号，或者调大在途上限（国际版风控更紧，调大前先小幅试）；`rpm_full` 时调大每分钟请求数上限；
- 排队期间客户端收不到任何数据，流式请求的首字会晚到，客户端的超时要比排队上限长。

## 503「no account in this API key's groups」是什么

用的客户端密钥在面板「密钥」里勾了账号分组，这个请求只能用这些组里的号，而组里的号此刻都接不了（冷却、禁用、暂停、这个模型冷却或被屏蔽、积分保底拦着），网关不借组外的号。在面板账号池按分组筛出来看这些号的状态，或者往组里加号；不想限了就在密钥里把分组都去掉。见[网关与选号 · 选号策略](gateway.md#选号策略)。

## 请求被上游内容审核拦截

Claude Code、Codex 等客户端的系统提示词里有固定模板句，可能被上游审核误拦：

- 默认 `prompt.mode=passthrough`：遇到拦截，网关会在同一请求内换成中性提示词自动重试一次，当天后续请求直接用中性提示词。
- 仍频繁被拦时，改成 `custom`（用网关自带提示词替换）或 `append`（在客户端提示词后追加）。
- 如果换了提示词仍被拦，说明是对话内容本身触发了审核。

详见[网关与选号 · 系统提示词与内容审核](gateway.md#系统提示词与内容审核)。

## 大上下文请求报 read body: i/o timeout

入站请求体上传超过了 `server.read_timeout`（默认 300 秒），常见于经过多层反代转发的大请求。调大这个值（`0` = 不限制）后重启。网关本身不限制请求体大小。

## 账号被禁用了怎么恢复

- session 连续 3 次失效会被自动禁用，原因写在面板账号状态与 `/status` 的 `disabled_reason` 里。
- 面板账号行点「解冻」可以直接复活；token 确实失效的，用「添加账号」重新登录同一个账号覆盖凭证。

## 多个账号共用一个 IP，怎么一次只用一个

在面板里对暂时不用的账号点「**暂停选号**」：它们不再接请求，但签到、保活、余额刷新、成长任务照常进行。需要时点「恢复选号」立即回池。详见[禁用、暂停与企业版账号](tasks.md#禁用暂停与企业版账号)。

想让号各走各的 IP，用面板「代理」页的代理池：号绑在池上，各分一个代理，池里还能限每个代理最多几个号，见[按号代理与代理池](proxy.md)。

## 官网积分记录的「使用端」显示什么

官网按出站请求的 User-Agent 归因。默认 UA 按账号所在域对齐官方桌面端：国内版 `WorkBuddy/5.9.3 WorkBuddy/5.9.3 CLI/2.165.0`，国际版 `WorkBuddy/5.9.4 workbuddy-ai/5.9.4 CLI/2.165.0`；需要时可用 `upstream.user_agent` 整体覆盖，或用 `upstream.client_version` / `upstream.cli_version` 只改版本号。改完需要重启。
