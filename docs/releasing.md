# 发版与版本号

本仓库从 1.0.0 起按[语义化版本 2.0.0](https://semver.org/lang/zh-CN/)独立编号，不再沿用上游的版本号。版本号写在 `cmd/server/main.go` 的 `appVersion`，每一版的变更记在[更新日志](CHANGELOG.md)。

- [什么时候升哪一位](#什么时候升哪一位)
- [发版步骤](#发版步骤)
- [更新日志的格式](#更新日志的格式)

## 什么时候升哪一位

| 改动 | 升哪一位 | 例 |
|---|---|---|
| 不兼容的改动，升级要手动处理：配置项改名或删除、旧配置不能沿用的默认行为变化、接口返回结构不兼容、镜像路径或启动参数变化 | 主版本号 | 1.4.2 → 2.0.0 |
| 向下兼容地新增功能：新视图、新配置项、新接口、同步上游带来的新能力 | 次版本号 | 1.4.2 → 1.5.0 |
| 向下兼容的问题修正，以及文案、样式之类的小调整 | 修订号 | 1.4.2 → 1.4.3 |
| 只改 CI、文档、测试，使用者感觉不到 | 不升 | — |

- 升主版本号时次版本号和修订号归零，升次版本号时修订号归零。一次推送里有多种改动，按最高的那一级升。
- 想先给少数人试用，可以发预发布版本，如 `1.5.0-rc.1`：Release 标为预发布，镜像只打 `1.5.0-rc.1` 一个标签；跑正式版的面板不会提醒预发布版本。
- 合并上游时，上游自己的版本号不影响本仓库：`appVersion` 冲突一律保留本仓库的值，上游版本只记在[同步记录](upstream.md#同步记录)里。同步带来使用者看得到的变化时，按上表升版本号，并在更新日志里写「同步上游至 `xxxxxxx`：……」。

## 发版步骤

推送即发版，不手动打 tag：

1. 改完代码，按上表定好新版本号，改 `cmd/server/main.go` 的 `appVersion`。
2. 在 `docs/CHANGELOG.md` 顶部加这一版的条目（格式见下节），日期写推送当天。
3. 提交并推送到 `main`。`go test` 会核对 `appVersion` 与更新日志最新一版一致，对不上 CI 直接失败。

推送后 CI 自动完成：

| 工作流 | 做什么 |
|---|---|
| go-binaries | 五平台构建；打 `vx.y.z` 标签，建标题为 `vx.y.z` 的 Release，说明取更新日志里这一版的内容，附带版本号的包和 `checksums.txt`，并标为 Latest。同时照常覆盖「最新构建」Release |
| docker-ghcr | 镜像照常推 `latest`、`main`、`sha-xxxxxxx`，另加 `x.y.z`、`x.y`、`x` 三个标签 |

CI 以 `vx.y.z` 标签是否已经存在来判断这次推送有没有升版本号。版本号没变的推送只更新「最新构建」和 `latest` 镜像，不碰已发布版本的 Release 和镜像标签。如果某次发版中途失败、标签没打上，下一次推送会补发。

面板的[一键更新](panel.md#一键更新)直接下载这个 Release 里的 `wb2api-panel-vx.y.z-<系统>-<架构>.tar.gz`（包的根目录要有 `wb2api`）和 `checksums.txt`，再用 `wb2api -version` 试运行。改打包方式、文件名，或去掉 `-version` 参数，都会让一键更新失效，要同步改 `internal/selfupdate`（测试会核对工作流里的包名和打包命令）。推送后到 Release 建好之前点一键更新，会提示 CI 还在构建。

## 更新日志的格式

格式参考 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)。面板的更新提醒、升级后的「本次更新」和 Release 说明都从这份文件解析，所以下面几条要守住：

- 版本标题写成 `## [x.y.z] - YYYY-MM-DD`，版本号不带 `v`，新版本写在最上面。`[未发布]` 这类不是版本号的标题会被跳过。
- 分组标题用 `### 新增`、`### 变更`、`### 弃用`、`### 移除`、`### 修复`、`### 安全`，没有内容的分组不写。
- 条目以 `- ` 开头，写给使用者看：做了什么、在哪里用、要不要手动处理，不写实现细节。一条写不下时，续行缩进两格。
- 需要整体说明的（如升级注意事项），写在版本标题和第一个分组之间。
- 行内只用反引号代码和链接。链接到 `docs/` 里的其他文档用相对路径，面板和 Release 说明会补成 GitHub 上的地址。

网关每 6 小时读取一次 `main` 分支上的这份文件（见[更新提醒](panel.md#更新提醒)）。推送后到镜像构建完成之间有几分钟空档，这期间检查到新版本的用户，可能要稍等一会儿才能拉到新镜像。
