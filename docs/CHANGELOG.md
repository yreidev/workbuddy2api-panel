# 更新日志

本文件记录每个版本面向使用者的变更，格式参考 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)，版本号遵循[语义化版本 2.0.0](https://semver.org/lang/zh-CN/)：

- 主版本号：配置、接口或部署方式出现不兼容的改动，升级需要手动处理；
- 次版本号：向下兼容地新增功能；
- 修订号：向下兼容的问题修正。

条目按「新增 / 变更 / 弃用 / 移除 / 修复 / 安全」分组。面板的更新提醒读的就是这份文件，发版规则见[发版与版本号](releasing.md)。

## [1.13.0] - 2026-11-01

号可以分组、设优先级了：主力号先用，都忙了才用备用号；客户端密钥可以只用某几组的号。上游说这类号不能用的模型（`11158`）现在一直屏蔽，不再隔几小时又撞一次。

升级注意：向下兼容。号的优先级默认都是 0，不分组、不设优先级就和以前一样；1.12.0 及以前因为 `11158` 正在避开的模型，升级后直接转进这个号的「不接的模型」名单。

### 新增

- 账号分组：账号池页下方建分组、改名、写备注、删，一个号可以在好几个组里。号在账号详情里勾，或者多选后「批量操作 → 加进分组 / 退出分组」；账号池能按分组筛。
- 客户端密钥可以勾账号分组：用它的请求只用组里的号，组里的号都接不了时回 503（`gateway_hint` 以 `key_groups` 开头），不借别的号；不勾 = 不限。见[网关与选号](gateway.md#选号策略)。
- 号的优先级：账号详情里设，0～99，越小越先用，默认 0；多选后可以批量设。选号只在优先级最高、此刻能接的那一层里挑，那一层都忙、冷却或接不了才用下一层；主力号空出来后，对话会回到主力号上。
- 每个号有一份「不接的模型」：选号时不把这些模型派给它。上游回 `11158` 时自动加上，也可以在账号详情里手动加（支持 `*` 通配），多选后能批量加、删。见[管理面板](panel.md)。

### 变更

- 上游回 `11158`（这类账号不能用这个模型）时，这个号的这个模型一直屏蔽，直到在账号详情里点 × 解除，或者指定这个模型测活通过；以前是避开 6 小时后再试。`11102` 照旧。
- 代理页不再把代理池叫「号的分组」，免得和账号分组混。

### 修复

- 测活自动挑模型时，会挑中这个号不能用的模型（比如国际版免费号挑中 deepseek），号本身没问题却记成不通。现在跳过这个号不接的模型，被上游拒了就换下一个最便宜的再测，最多换 2 次。

## [1.12.0] - 2026-11-01

可以限每个号每分钟接几个请求了；账号池勾选账号后能批量测活、暂停、解冻、禁用、移除。另外修了启动时模型目录没拉到就一直缺目录的问题。

升级注意：向下兼容。每号每分钟请求数上限默认不限，不设就和以前一样，老配置不用改。

### 新增

- 每号每分钟请求数上限：`pool.max_rpm` 管国内版、`pool.max_rpm_global` 管国际版，默认 `0` 不限。按最近 60 秒算，到了上限的号和在途占满一样当作忙：换别的号，能接的号都忙时排队，最多等 `pool.in_flight_wait`，等满回 503，错误里写明是每分钟请求数到了上限（`gateway_hint` 以 `rpm_full` 开头）。面板「配置 → 账号池与流量治理」里可改，保存即生效，见[网关与选号](gateway.md#选号策略)。
- 账号池勾选账号后多了「批量操作」：测活、暂停选号、恢复选号、解冻、禁用、移除，逐号执行，做完提示几个成功、几个失败，失败的列出原因；禁用和移除先确认。要清掉被限制的号：点「已禁用」筛出来，全选，「批量操作 → 移除」。见[管理面板](panel.md)。

### 变更

- 「配置 → 账号池与流量治理 → 跨域负载均衡」的说明改直白：打开后 `/v1/models` 会多列出不带 `cn:` / `global:` 前缀的模型名，用这种名字请求时在国内版、国际版账号里选号；带前缀的名字照旧只走那一域。
- 账号池顶部的「N 个账号在途占满」改成「N 个账号满载」，每分钟请求数到上限的号也算进去。

### 修复

- 启动时模型目录没拉到（没有可用的号、上游出错）的话，以前要等有人调 `/v1/models` 或打开模型页才补拉：这期间开着跨域负载均衡时，不带前缀的模型名全落到国内版（没有国内版号就一直 503），积分保底也判不出模型收不收费。现在没拉到的域每分钟补拉一次，拉到的每 30 分钟刷新。

## [1.11.0] - 2026-11-01

每个号可以走自己的代理了：号绑到代理池上，池里分一个代理固定用，号就从这个代理的 IP 去连官方，不用再全挤在服务器一个 IP 下。代理坏了或到期只停绑在上面的号，久了自动改绑，从不退回服务器 IP。

升级注意：向下兼容。不建代理池就和以前一样，号走环境变量里的代理或直连；建了池也只有绑上去的号走代理，现有的号不会自动放进去。

### 新增

- 面板新增「代理」页：建代理池（号的分组），批量粘贴或上传 txt 导入代理，先预览哪几行认不出、哪几行和已有的重复再导；可以导出备份（带密码）、设到期时间，单个测试、修改、删除。见[按号代理与代理池](proxy.md)。
- 号绑在池上，池里按绑号最少分一个代理后固定；单个号也可以直接指定代理。国内版、国际版各可设一个默认池，新登录、导入的号自动进去。池可以限每个代理最多几个号，满了新号先等着，加了代理或调高上限自动补上。
- 绑定入口：账号池勾选后点「绑定代理」（绑到池、单独指定、解绑），账号详情里改绑，代理页的池卡片上「重新均分」；添加账号时选池，登录请求本身就走分到的代理；导入凭证时也能选池，凭证里带 `proxy_url` 的认出这个代理，导出凭证也带上。
- 自动检查代理：默认每 5 分钟经代理连一次官方入口，测通不通和延迟；每小时经代理查一次出口 IP（先 ip-api.com，再 ipify，地址可以换），标出出口重复、和服务器同 IP、IP 变过的代理。
- 代理连不上、测不通或到期时，绑在上面的号暂停选号、不罚号，请求直接换号；账号池多一栏「因代理暂停」，卡片写明原因。连续不可用超过 30 分钟、同池有能用的代理时，号自动改绑。到期前 3 天在代理页和账号池页提醒。
- 「只许走号的代理」开关（默认关）：开了以后没绑代理的号不接请求、不跑定时任务。
- 账号卡片、表格和详情显示号走的代理和出口 IP，请求记录多了代理名，也能按代理名搜。
- 签到、查积分、领试用、命令行登录这几个工具也按号走代理，`login.sh` 可以加 `--pool=池名` 选池。

### 变更

- 风控波暂停和 WAF 拦截按出口分开算：被限的号都在同一个出口时，只暂停这个出口下的号；不用代理池时和以前一样。
- 绑了代理的号，国内版主入口出错后改用 HTTPDNS 地址或备用 IP 重发时也走号的代理，不再从服务器 IP 出去。

## [1.10.0] - 2026-10-31

每个号都能测活了：给号发一条最短的真实对话，看它现在能不能用；限流冷却、熔断中的号每 30 分钟自动测一次，测通就提前恢复，不用干等冷却到期。

升级注意：定时测活默认开启，升级后自动开始跑。它只测整个号在限流冷却、熔断中的号，但会真的发对话、可能扣一点积分；不想要就在「配置 → 定时任务」里关掉，或设 `schedule.liveness_enabled: false`。其余都向下兼容，老配置不用改。

### 新增

- 账号测活：账号卡片、表格和详情里的「测活」给这个号发一条最短的真实对话（「hi」），走和真实请求同一条路径，只是不换号。弹窗里模型默认挑这个号目录里积分倍率最低的，可以临时换；测完显示通不通、首字和总耗时、扣的积分、失败原因和上游回复。账号池的「全部测活」在后台测所有没被人工禁用的号。卡片、表格和详情显示上次测活，重启不丢。见[测活](panel.md#测活)。
- 定时测活（`schedule.liveness_enabled`、`schedule.liveness_minutes`，默认开、每 30 分钟）：只测整个号在限流冷却、熔断或连败降权中的号；余额不足、风控波暂停、只是某个模型被限额、禁用、暂停选号的号不测。
- 测通了提前解除这个号的冷却和熔断，网关自动加的禁用也解除；人工禁用、暂停选号、风控波整域暂停不动。测不通照真实请求处置，但人工禁用的号不会被改成网关自动禁用，已经禁用的号再回 `11140` 也不会触发风控波整域暂停。
- 测活记进请求记录（密钥一列写「测活」）和这个号的用量（用量页按密钥分时叫「测活」），不算任何客户端密钥的用量。

## [1.9.0] - 2026-10-31

挑进原版 linguo2625469 停更前的最后一批改动（见[同步记录](upstream.md#停更前最后一批)）：Claude Code 自带的联网搜索直接能用，Codex 接网关的 MCP 服务器也能搜；新增积分获取流水、账号备注、隐藏模型、出站代理与 DNS、跨域「国内版优先」；上游容量排队照官方等到号再发。出站请求跟上国际版桌面端 5.9.4，积分、签到请求的形状也改成官方实际发的样子。

升级注意：环境里本来就设了 `HTTPS_PROXY`、`HTTP_PROXY`、`ALL_PROXY` 这类代理变量的部署，升级后发给官方的请求会开始走代理；不想走就去掉这些变量，或用 `NO_PROXY` 排除。其余都向下兼容，老配置不用改。

### 新增

- 联网搜索：Claude Code 自带的 WebSearch 不用配，直接能用；新增 MCP 端点 `/mcp`（只有一个 `web_search` 工具），Codex 照 README 里的配置接上就能联网搜索；`/v1/search/messages` 也可以直接调。选号、换号和对话一样，客户端密钥每搜一次计一次请求。面板密钥的「接入方法」里有 Codex 的配置片段。搜一次扣不扣上游积分还没实测。见[联网搜索](api.md#联网搜索)。
- 面板新增「积分获取」页：签到、成长任务领奖、积分补偿、猫猫旅行、新手礼包、连登兑换领到的积分逐笔记下来，按时间、账号、来源查。留存在「配置 → 日志留存」里设（`logging.credit_log_*`，默认永久保留）。升级之前领的没有记录。
- 账号备注：在账号详情里给账号写一句备注，存在网关上，各页的账号名都先显示备注。
- 隐藏模型（`models.hidden`）：在「模型与档位 → 对外隐藏的模型」里加，`/v1/models` 不列，点名调用回 400 `model_unavailable`。见[隐藏模型](api.md#隐藏模型)。
- 模型页加「状态」列：按模型锁和最近一次真实请求标出每个模型现在能不能用，两个域都标，悬停看依据。
- 出站代理：发给官方的请求照官方客户端读 `HTTPS_PROXY`、`HTTP_PROXY`、`ALL_PROXY`、`NO_PROXY`，支持 http、https、socks5 代理，走代理时 TLS 握手指纹照样伪装。见[出站代理](configuration.md#出站代理)。
- 出站 DNS 可以指定：`dns_servers`（环境变量 `WB2A_DNS`），给没有 `/etc/resolv.conf` 的环境用，需重启。
- `pool.cross_realm` 加一档 `cn_first`（国内版优先）：国内版此刻有能接的号就只用国内版，没有才用国际版。老配置的 `true` 读成 `merge`（合池）。面板「配置 → 账号池与流量治理」里可选，见[跨域负载均衡](gateway.md#跨域负载均衡)。
- 认出「企业切换会话」的号（浏览器停在企业空间时登录的个人号）：成长任务、连登、旅行这些做了也不计分，网关跳过并在账号上标出来，提示重新登录。

### 变更

- 上游回 `6020`（容量排队中）时，照官方在原来的号上排队、到号后重发，最多等 `pool.in_flight_wait`（默认 30 秒），等不到回 503；`6022`（这个号排队数到上限）换下一个号。
- 成长任务排程和「执行全部待办」会顺带领掉已达标还没领的奖，包括靠真实使用点亮的任务；「一键完成」遇到这种任务也先补领。
- 积分包到期时刻照官方按包类型取：订阅、体验这类按周期刷新的包按刷新时刻算，不再显示成好几年后到期；到期提醒和快过期加权用同一个口径。
- 出站请求跟上国际版桌面端 5.9.4：国际版按 `5.9.4` / CLI `2.165.0` 发 UA 和 `X-IDE-Version`，两个域的对话都带 `X-Agent-Runtime`。
- 积分查询、签到、企业用量照官方后台服务实际的请求形状发（UA `axios/1.16.1`，不再带 `X-Requested-With`、`X-Product`、`X-Department-Info`）；国际版后台请求和刷新令牌的 UA 改成 `workbuddy-ai/<版本> workbuddy-ai/<版本> CLI/<版本>`。积分查询照官方新版：国内版纯免费号不再查付费包，付费包多了 BuddyOne 会员。见[官方客户端对照](official-client.md)。
- 成长中心接口的 `Accept-Language` 照官网设成 `zh-CN`。
- 积分补偿弹窗里，离领取截止不到 48 小时的标红，写明还剩几小时。

### 修复

- 部门额度、企业资源包用完（`14022`、`14023`）按余额不足冷却到次日 04:00，以前当普通错误换号。
- 冷却到期后，账号状态不再挂着过期的冷却原因。
- 模型级限额同时写出网关重试时刻和上游恢复时刻，倒计时跟网关。
- 同一个号同时只发一个刷新令牌请求；刷新回 `12153` 时改用凭证文件里别的进程换过的令牌再刷一次。
- 上游排队满（`6021`）不罚号、不换号，直接回 503。
- 模型无权限（`11158`）按号避开，可选的号都没权限时回 400 `model_unavailable`，面板也显示成「模型不可用」。
- 消息里的思考片段（`reasoning_text`）发上游前去掉，避免 `11101`。
- 缓存命中为 0、未命中很小时按 prompt 反推命中，不再误报整段未命中。
- 拉国内版模型目录失败时记一行 WARN。

## [1.8.0] - 2026-10-28

出站请求照官方桌面端新版（国内版 5.9.3、国际版 5.8.4）又对齐了一轮：版本号、链路与风控请求头都跟上，TLS 握手也默认伪装成官方客户端的指纹，整体更难被按客户端特征识别。都是向下兼容的改动，升级不用改配置。

### 新增

- 出站 TLS 握手默认伪装成官方桌面端客户端的握手指纹，降低被按握手特征识别的概率。新配置项 `upstream.tls_fingerprint`（默认开，环境变量 `WB2A_TLS_FINGERPRINT`），关掉回落到旧的标准库握手；改后重启生效，对新建连接起用。见[配置](configuration.md)。

### 变更

- 出站的版本号与请求头对齐官方桌面端新版：国内版按 `5.9.3` / CLI `2.165.0`、国际版按 `5.8.4` / CLI `2.161.0` 发 User-Agent 和 `X-IDE-Version`，国内版对话补发 `X-Agent-Runtime`。需要时仍可用 `upstream.client_version` / `upstream.cli_version` 覆盖。见[官方客户端对照](official-client.md)。
- 对话按官方补齐 OpenAI SDK 发出的 `Accept` 和一组 `X-Stainless-*` 头，取值照官方桌面端内置的运行环境。
- 对话也带设备风控头 `X-Device-Token`，但只在填了 `upstream.device_token`（或凭证文件里的 `device_token`）时才带，没填就不带。见[配置](configuration.md)。
- 云端 / 付费专家的对话按官方加内容审核头 `X-Moderation-Type`，普通对话不受影响。
- `X-Private-Data`（是否允许上游用对话做模型优化）按官方新版调整判断：默认仍发「不允许」，打开 `upstream.model_optimization` 时个人号发「允许」、企业号仍「不允许」。见[配置](configuration.md)。

### 修复

- `WorkBuddy_Valorant`（无畏契约拼豆专家）任务：2026-10-28 在真实账号上实测，按名字搜索后能召唤、对话、点亮，去掉了之前「可能需要官方客户端」的试探提示。

## [1.7.0] - 2026-10-28

新增日志留存：请求记录、任务日志、系统日志、用量统计各设保留天数，运行日志能按时间范围查历史。能接请求的号在途都满时，请求先排队等空位，不再马上回 503。客户端没带会话 id 的对话，换了号也接着用原来的上游会话 id。`WorkBuddy_Valorant` 改成照官方专家页按名字搜索专家。

### 新增

- 日志留存：请求记录、任务日志、系统日志、用量统计各设保留天数，在配置页新的「日志留存」分组里改，保存即生效。任务日志和系统日志按天写进数据目录的 `runtime-logs/`，默认保留 30 天、容量上限分别是 20 MiB 和 50 MiB，可以分别关掉；用量统计默认永久保留。每类卡片下面显示现有的文件数、大小和最早日期，可以一键清空（要再确认一次）。见[日志留存](configuration.md#日志留存)。
- 运行日志页加了「历史」：按时间范围（今天、近 7 天、自定义等）从磁盘上的留存里查任务和系统日志，频道、级别、关键字照样能筛，一次最多 5000 行，不是今天的行带上日期。「实时」还是最近 500 行。
- 号都满时排队（`pool.in_flight_wait`，默认 30 秒）：能接这个请求的号都健康、只是在途都满了时，请求等其中一个号放出名额再转发，一个请求合计最多等这么久，等的时间不算换号次数。等满仍没有空位才回 503，错误信息写明是号都在忙（`all accounts are busy`）。号在冷却、禁用、暂停，或者被模型级冷却、积分保底拦下时不排队，照旧马上回错；设成 `0` 回到以前的做法。面板「配置 → 账号池与流量治理」里可以改，保存即生效，见[网关与选号](gateway.md#选号策略)。

上游错误按官方客户端的错误码表重新归类，国际版 deepseek 不再因为一次「模型繁忙」整号停十分钟；客户端发来的压缩请求体也能正常处理了。

- 客户端发来压缩过的请求体（`Content-Encoding` 为 gzip、deflate、br、zstd，或没标头但内容是 gzip）时网关先解开再处理。以前原样转给上游，上游回 `11101`（`invalid character '\x1f'`），生产 10-19 至 10-20 有四十多次。解不开或不是合法 JSON 的请求在网关就回 400，不再打上游。

  - 对话换地址：DNS 解析失败时先换地址再换入口；408、502、503 和传输错误在换不了入口时换地址（504 不换）。候选地址是腾讯云 HTTPDNS 查到的 IP，备用入口另加官方内置的备用 IP；请求钉到这个 IP 上发，域名和证书校验不变。30 秒内失败过的 IP 跳过，上次成功的排第一个；同一请求换过的地址记住，后续重发沿用；
  - HTTPDNS 照官方：调用方最多等 600 毫秒，查询本身不取消、查完写进缓存；单个请求连续 300 毫秒没有收发才算超时；结果缓存 300 秒，过了 225 秒在后台续期，续期时现取服务 IP 列表；缓存没命中时每次各查一路；
  - 拉模型目录：5 秒总预算内依次试主入口、备用入口、备用 IP，408、502、503、传输错误或返回的目录无效时换下一个；
  - 登录与刷新令牌不换入口（官方也不换）；发起授权和刷新令牌在 408、502、503、传输错误或返回无效内容时依次换 HTTPDNS 地址重发。每次尝试单独计时：发起授权、刷新令牌 8 秒，轮询、取账号 4 秒；
  - `chat_base_cn` 配成备用入口时只换地址，配成别的地址时整套不生效；
  - 生产（美国机房）实测：HTTPDNS 查到三个入口的 IP，钉到每个 IP（含备用 IP）拉模型目录都成功。这种网络下一次完整查询约 1.4 秒，第一次按没有结果返回，之后命中缓存。

  见[官方客户端对照](official-client.md#备用入口)。
- 配置项 `upstream.model_optimization`（面板「上游与高级 → 出站请求」里的「允许上游用对话做模型优化」），默认关闭：每条对话都带 `X-Private-Data: true`。两个安装包的产品配置都让「模型优化」默认关闭，所以这就是官方客户端没动过这个开关时的行为。打开等于在桌面端打开这个开关：个人号发 `false`，企业号仍发 `true`（新版官方 CLI 对企业号一律不允许）。保存即生效，见[配置](configuration.md)。

### 变更

- 客户端没传 `conversation_id` 时，同一段对话的 `X-Conversation-ID` 不再每轮都换：对话的第一个请求新生成一个；历史里出现第一条助手回复以后，按「账号 + 系统提示词 + 第一条用户消息 + 第一条助手回复」认出这段对话，第一次认出时生成一个记在内存里，此后整段对话不变，两个域相同。记录在最后一次使用后保留 2 小时，网关重启或隔了更久再接着聊会换一个新 id，上游缓存断一次。官方客户端也是整段对话用同一个会话 id，上游的前缀缓存按它命中：实测 `glm-5.2` 在会话 id 稳定时第二轮 8 次全部命中，每轮换新 id 只命中 3/10，没命中的一轮积分是命中时的 3 倍多。加上第一条助手回复，开头逐字相同的两段不相干对话仍会拿到不同的 id；两个域、4 个模型共 29 次串会话测试，都没有带出别的对话的内容。1.1.0、1.1.1 里「每轮新生成」「国内版客户端没给就不发」的做法由此取代，见[会话粘性](gateway.md#会话粘性)。
- 会话 id、轮次 id、消息 id 改成官方的形状（内置 CLI 2.161.0 的 `uuidv7()`）：会话 id 是带连字符的 36 位 UUID v7，轮次 id 和消息 id 是去掉连字符的 UUID v7，前 48 位都是生成时的毫秒数。以前都是随机或哈希出来的 32 位十六进制，按内容派生的会话 id 和轮次 id 现在第一次派生时生成、记在内存里。链路头的 span id 改为每条消息单独随机，不再截消息 id。
- 任务中心和各类上报不再发带网关名字的 id：以前对话活跃上报、夜间对话、领养前置、连登上报、任务中心的事件链里，会话 id、轮次 id 是 `wb2api-rm-…`、`wb2api-tpl-…`、`wb2api-<毫秒>` 这类自造值，消息 id 是 `msg-pb`、`msg-…-assistant` 这类值，定时任务的名字是「wb2api 自动化」。现在都用上面官方形状的 id，三个 `chat_message_*` 事件带同一个模型消息 id，定时任务名改成「每日资讯简报」。真发了对话的几处（夜间对话、体验模型的对话任务），上报和这次对话用同一个会话 id、轮次 id。
- 网关不再自动补 `prompt_cache_key`（客户端自己带的照转）。官方客户端不发这个字段，实测它也没有让哪个模型的缓存命中变多，`glm-5.2` 每轮换新会话 id 时带上它反而命中更少。1.0.0 同步自上游的「`prompt_cache_key` 回退到会话键」和 1.1.0 里「`prompt_cache_key` 仍按会话键区分不同对话」的做法一并去掉。
- 新会话分配账号时也看成本分层：先只留这个模型最便宜的一层（实测免费 > 尚无观测 > 实测收费，成本探索照常），再按会话键挑号。以前新会话不看成本分层，会绑到实测收费的号上，即使池里还有免费的号。已经绑定的会话不因此换号，见[选号策略](gateway.md#选号策略)。
- 企业号补上部门全名：官方给有部门全名的账号在桌面端请求上带 `X-Department-Info`、在上报事件里带 `enterprise`，网关以前没存这一项。现在登录时取账号就存进凭证文件的 `account.departmentFullName`（命令行登录工具和 `login.sh` 也写），1.1.2 以前的凭证文件在下一次刷新令牌时补上；有值才发，个人号不变。池里没有带部门的企业号，没有实测。
- 国内版请求全部改发官方产品入口 `www.workbuddy.cn`。以前对话、刷新令牌、登录、模型目录、成长任务和任务中心发往 `copilot.tencent.com`（官方的备用入口），积分、签到、积分补偿、开学季活动和小程序上报发往 `www.codebuddy.cn`（桌面端里只用于网页链接）。生产对比了两个域名：对话、模型目录、积分与签到状态、成长任务和猫猫旅行的查询、任务中心的专家列表、登录的发起授权和轮询，结果都相同。会改动账号状态的请求，网关本来就会自动做的几样用新代码在生产上真做了一次：两个域各刷新一个号的令牌、3 个号的旅行领奖、1 个号的旅行出发，都成功；其余的用必然失败的参数按新形状发（今天已签过的签到、没完成的任务领奖、不存在的兑换档位、没有次数的抽奖、已领过的积分补偿、小程序领不存在的任务等），都返回业务错误，说明路径和认证都对。面板添加国内版账号时打开的授权页随之变成 `www.workbuddy.cn`。详见[官方客户端对照](official-client.md#国内版域名)。
- 对话请求：
  - 补上官方每条都带的 `X-Agent-Intent`、`X-Agent-Type`、`X-Private-Data`、W3C `traceparent` 与单行 `b3`；企业号多带一个与企业 ID 同值的 `X-Tenant-Id`；
  - 带了思考档位时补 `reasoning_summary: "auto"`；
  - `X-Product` 由 `WorkBuddy` 改成 `SaaS`：官方请求框架给经过它的每个请求都加部署类型，两个安装包都是 `SaaS`；
  - 去掉官方对话请求里没有的头：`Origin`、`Referer`、`Accept-Language`、`X-CodeBuddy-Request`、`X-Machine-ID`、`X-Session-ID`、`X-Root-Request-ID`、`X-Device-Token`，以及个人号的 `X-No-Enterprise-Id`、没有登录域时的 `X-No-Department-Info`；
  - User-Agent 改成内置 CLI 的取值：国内版 `WorkBuddy/5.8.3 WorkBuddy/5.8.3 CLI/2.161.0`，国际版 `WorkBuddy/5.8.4 workbuddy-ai/5.8.4 CLI/2.161.0`；`X-IDE-Version` 跟着改成 5.8.3 / 5.8.4。
- 积分、签到、上报、外观、专家列表这些请求改成桌面端后台服务的形状：
  - UA 由单段的 `WorkBuddy/5.5.4` 改成 `<应用名>/<版本> WorkBuddy/<版本> CLI/2.161.0`，应用名国内版是 `WorkBuddy`、国际版是 `workbuddy-ai`；
  - 补上官方请求框架每个请求都带的 `X-Requested-With`、`X-Product: SaaS` 和 `X-Request-ID`（32 位十六进制，每次新生成）；`X-Domain` 改成登录域（任务中心几个请求以前填的是带 `https://` 的完整地址）；
  - 不再带 `X-CodeBuddy-Request`；
  - `Accept-Language` 只在积分查询上带，值为 `zh` 或 `en`（以前每条都带 `zh-CN` / `en-US`）；
  - `X-Device-Token` 只在签到上带。
- 各类请求的 `Accept-Encoding` 照官方各自的取值发（以前都是 Go 默认的 `gzip`）：
  - 桌面端的请求（对话、刷新令牌、登录、模型目录、积分、签到、上报等）是请求框架 axios 的 `gzip, compress, deflate, br`；
  - 网页登录码请求是 Node 内置 fetch 的 `br, gzip, deflate`，另补它默认带的 `Accept-Language: *`、`Sec-Fetch-Mode: cors`；
  - 官网网页和国际版注册页是 Chrome 的 `gzip, deflate, br, zstd`，小程序网页是 iOS WebKit 的 `gzip, deflate, br`；
  - 响应按 `Content-Encoding` 解压，br、zstd 用 [andybalholm/brotli](https://github.com/andybalholm/brotli)、[klauspost/compress](https://github.com/klauspost/compress)。生产实测上游目前不压缩响应，对话流照常。

  - 官网网页、client-login 和国际版注册页的 UA 改成 Mac 上的 Chrome 152（国际版注册以前是 Windows 上的 Chrome 120），`Sec-CH-UA-Platform` 改成 `"macOS"`；
  - 网页上报照官网前端的公共参数：`os` / `osVersion` 由 UA 解析（`macOS` / `10.15.7`，以前是 `Win32` / `10.0`），补上 `sessionId`、`username`、`type`、`product: UserCenter`，`machineId` 改成 32 位十六进制，去掉 `arch`；
  - 生产实测这几种上报都返回成功，成长任务列表正常。见[官方客户端对照](official-client.md#设备与平台)。
- 积分查询改用官方桌面端的三个接口：汇总、付费包、免费包同时查，两个域路径相同。余额以汇总为准，单包额度按官方读精确值字段。以前的 `/v2/billing/meter/get-user-resource` 在官方 5.8.3 里已经没有了；生产对比，按旧接口整数字段算出的余额和官方汇总对不上，新算法一致。命令行积分工具 `cmd/credit` 改用同一套查询，企业号改查企业额度，不限量的企业号标 `unlimited`、不计入总计。见[官方客户端对照](official-client.md#积分与签到)。
- 签到前先查签到状态：活动没开或今天已签就不再发签到请求（官方桌面端也是先查状态，用户点了才签）。国际版不再先试一遍不带 `/v2` 的签到路径。
- 成长中心（任务、猫猫旅行、连登、抽奖、补签卡、兑换）、积分补偿、新手礼包、试用、账号资料（同步昵称）改成官网网页的形状：这些接口官方只在官网网页上调，桌面端点“成长中心”打开的就是浏览器。请求发往官网域，带 `X-Client-Platform: web` 和浏览器的 UA、客户端提示（`Sec-CH-UA*`）、`Sec-Fetch-*`，不带 `X-User-Id`、`X-Domain` 等桌面端的头。认人照官方的流程用网页登录态：先用账号令牌换一次性登录码（`POST /v2/plugin/device/auth/code`），再打开 `/console/client-login` 换到 session Cookie（照浏览器跟随它的跳转打开目标页），之后这些请求只带 Cookie、不带 `Authorization`；Cookie 失效（401）时自动重取一次。每个账号一份登录态，只存在内存里，重启后重取。另外：任务列表先查订阅任务状态；接受任务改用不带 `/v2` 的路径；领奖、领养等不再带空请求体，旅行领奖发 `{}`；兑换、抽奖的 `client_token` 带上网页的前缀；新手礼包先查领取状态，开放且没领过才领。国际版没有成长体系，任务列表直接返回空，不再请求上游。见[官方客户端对照](official-client.md#官网网页的请求)。

- 刷新令牌改成官方的形状和流程：
  - 请求体 `{}`（以前没有请求体），仍带 `X-Auth-Refresh-Source: plugin`，补上 `X-Product: SaaS`、`X-Request-ID` 和根 span 的链路头，去掉官方没有的 `Origin`、`Referer`、`Accept-Language`、`X-CodeBuddy-Request`、`X-Machine-ID`、`X-Session-ID`；
  - 刷新成功后用新令牌取一次账号（国内版 `/v2/plugin/account`，国际版 `/v2/plugin/accounts`），照官方挑出对应的那个账号，把昵称、部门全名等合并进本地，再照官方比对身份（账号类型、企业 id、`oneidAccountId`、部门全名、`idp`、令牌的 `tokenType` 和登录域），变了就当刷新失败；取不到账号、新令牌和旧的一样也当失败，新令牌不写回。为此凭证文件多存账号的 `type`、`oneidAccountId`、`idp` 和令牌的 `tokenType`，1.1.2 以前的文件第一次刷新时补上、不比对。uid 对不上照官方保留本地账号、照常用新令牌（以前当刷新失败）；
  - 生产实测两个域各刷新一个号：两个令牌都换了，旧的访问令牌刷新后仍能用；有效期国内版 30 天、国际版约 1 年。
- 模型目录：
  - 个人号只用内置 CLI 的 UA 拉一次 `/v3/config`，拉到的和官方桌面端是同一份；请求头同样是官方请求框架的形状；
  - 不再换成 IDE、CLI 的 UA 各拉一遍，也不再调只给企业号用的企业模型接口；
  - 企业号改用官方的企业模型接口 `/console/enterprises/{企业 ID}/config/models`（两个域都是），带 `chat` 标签的模型并进名单，和 `/v3/config` 合并。以前国内版用 `/console/enterprises/personal/models`、国际版用 `/v2/enterprises/personal/models`，都不是官方的接口。池里没有企业号，没有实测；
  - 名单更准：去掉的 `glm-4.7`、`glm-5.0`、`o4-mini`、`auto-chat`、`deep-model` 实测都用不了；国内版新增 18 个、国际版新增 8 个；带思考档位的模型国内版从 12 个增加到 18 个，国际版从 10 个增加到 18 个。

  代价有三条：
  - 少数模型的可选档位收窄到桌面端的范围，例如国内版 `deepseek-v4-pro` 只有 high / xhigh，请求 low 会被提到 high，扣费更多；
  - 只在旧目录里出现的模型（国内版 `default`，国际版 `gpt-5.3-codex`、`enhance-1.0`）不再列出，但直接请求照样转发；国际版专属的名字不带前缀时默认发往国内版，要加 `global:` 前缀；
  - 国内版几个模型在 `/v1/models` 里显示的最大输出从 393,216 变成桌面端目录里的 128,000，这个值只用于展示，不截断请求。

### 修复

- 国际版账号对话被上游拒绝，返回 400 `code 11128`「request illegal」：1.1.0 起客户端没传 `conversation_id` 时网关不再发 `X-Conversation-ID`，国内版不受影响，国际版上游却要求必须带。现在国际版在客户端没给时用本轮新生成的轮次 id 补上，每轮都不一样，开头相同的两段对话不会撞成同一个会话；客户端给了照旧原样转发。国内版仍是客户端没给就不发。

## [1.1.0] - 2026-10-19

### 新增

- 导出凭证：账号池可以勾选账号后「导出凭证」，表头勾选框一次选中当前筛选结果，手机端在搜索框旁「全选」；单个账号在详情里导出。单个账号得到 `workbuddy-<uid>.json`，和数据目录里的凭证文件一模一样；多个账号得到一个 JSON 数组文件。文件里是能直接登录的凭证，请妥善保管。
- 企业版模型：每个国内版企业号单独拉一份自己的模型目录，拉的时候带齐企业身份（否则上游给的是个人号的名单）。只在企业号目录里出现的模型，比如企业开通的 Claude，会出现在 `/v1/models` 和面板「模型与档位」里并标「企业专属」，请求只派给目录里有它的企业号；别的号能用、企业号自己目录里没有的模型，也不再派给这个企业号。做法参考了 dsh-workbuddy-connect 与 cli2api，见[企业版模型](tasks.md#禁用暂停与企业版账号)。
- 导入认网关自己的凭证：「添加账号 → 导入 JSON」除了 cockpit tools 的文件，也能导入上面导出的文件（单个或批量），企业 ID、国内版 / 国际版、设备 token 原样保留，适合备份或迁到另一台网关。

### 变更

- Go 模块路径改为 `github.com/yreidev/workbuddy2api-panel`。只影响从源码编译或引用本仓库代码的人；镜像、二进制和配置不受影响。

### 修复

- 打开跨域负载均衡后，国际版账号几乎分不到不带前缀的请求：带会话的请求（客户端没传会话 id 时网关也会自己算一个，所以几乎是全部请求）分配账号时只在国内版号里挑。现在会话也在两域合池里分配，新会话可能绑到国际版号；已经绑定的会话不换号，等绑定过期（默认 30 分钟没有请求）、请求失败或绑定的号暂时用不了时才重新分配。
- 导入企业版账号时不再顺带签到（企业版没有签到，上游会拒绝）。
- 国际版企业号对话时不再声明「无企业」，改为带上企业 ID，与 cli2api、dsh-workbuddy-connect 的做法一致（国际版企业号尚未实测）。
- 客户端没传 `conversation_id` 时，网关不再把自己算出的会话键当作 `X-Conversation-ID` 发给上游。这个会话键只由系统提示词和第一条用户消息决定，开头相同的两段不相干对话会得到同一个值，上游可能把它们当成同一个会话。`prompt_cache_key` 仍按会话键区分不同对话，前缀缓存命中不受影响。
- 同样是客户端没传 `conversation_id` 时，两段对话的内容撞上不再共用同一个 `X-Conversation-Request-ID`：以前开头相同、中途走向不同的两段对话在同一位置发同一句话（比如「继续」），或者首轮逐字相同（同样的系统提示词和第一句话，中转站的渠道测试也是这样），上游会把它们并成一轮。现在每次用户发言新生成一个值，同一轮里的工具调用续轮凭网关转出去的工具调用 id 找回它，换号重试也沿用它，上游用量明细照旧按轮合并；网关重启时正在进行的那一轮会拆成两条记录，见[会话粘性](gateway.md#会话粘性)。
- 非流式请求：上游同时给了结构化的工具调用、正文里又带工具调用标记时，不再用从正文还原出来的调用覆盖真实的调用。
- 任务列表「全部接受」：常规任务都接受过时，不再直接回「所有任务均已接受」而漏掉还没接受的小程序任务（如小程序首对话）。
- 任务中心「使用平台专家」类任务：上游回复里同一段数据先出现别的 id、后出现服务端请求 id 时，不再误报「未找到服务端 requestId」。
- 国际版模型列表：`/v3/config` 探测全部失败、只剩企业端点而且它只给模型名时，不再当成探测失败（以前会把国际版号的模型列表清空）；探测到的模型顺序也固定按 id 排列，不再每次刷新都变。
- 连登奖励日志：奖品内容超长截断时不再把中文切成半个字（日志里会出现乱码）。
- 命令行签到工具 `signin_bin`：token 在两小时内过期时先刷新再签到。以前时长单位写错，只有已经过期的 token 才会刷新，快过期的 token 可能在签到途中失效。
